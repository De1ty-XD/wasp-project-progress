---

## 一、项目动机：为什么要做 WASP？

在大语言模型加速进入网络安全与研发安全（AppSec / DevSecOps）领域的背景下，依赖云端顶尖闭源模型开展自动化安全评估，正面临越来越明显的现实瓶颈：

1. **闭源模型的高门槛与强护栏限制**  
   头部闭源模型在网络安全方向持续收紧策略并提高使用门槛。即便是在**受控靶场研究、企业内部自查或合法授权测试**场景下，云端模型依然频繁触发过度拒答（Over-Refusal），导致多步骤评估链路随时中断；同时，高频长上下文交互带来的 API 费用也显著抬高了持续化测试成本。
2. **数据主权与内网隔离的刚性约束**  
   真实的 Web 安全评估往往涉及未公开业务接口、多角色测试凭据、内部数据结构与敏感状态流转，难以将完整流量上下文直接托管至外部云端服务。
3. **裸跑本地开源模型的能力代差**  
   将模型迁回本地虽能解决可控性与隐私问题，但中小规模开源模型在长程规划、多身份状态维护、复杂不变量推理和低误报裁决上，与顶尖闭源模型存在显著差距——直接以纯 Agent 方式裸跑，极易陷入上下文迷失与幻觉误报。

**WASP 正是为解决这一矛盾而发起的长期实验项目。**

---

## 二、核心理念：用确定性 Harness 抹平模型代差

WASP 的核心技术假设是：

> **复杂 Web 安全评估的瓶颈，并不完全在于模型参数规模，而在于“不可靠的概率推理”与“强确定性的安全验证”混杂在一起。**

与其等待更昂贵的云端大模型，WASP 选择通过系统工程构建一层厚实的**确定性验证脚手架（Deterministic Harness）**，将原本极易出错的工程环节从模型负担中剥离出来：

| 分工维度 | 本地大语言模型（LLM）负责 | 确定性 Harness 负责 |
|---|---|---|
| **核心职责** | 业务语义理解、接口关联、探索路径决策 | 资产建图、多角色会话切换、协议预检、确定性断言与证据链审计 |
| **能力优势** | 泛化理解不同业务场景与隐式逻辑 | 强一致、可复现、抗幻觉、低开销 |
| **工程目标** | 聚焦高价值的语义探索与假设提出 | 把“猜测”收口为可审计的四态证据结论 |

通过这种**神经符号协同（Neuro-Symbolic）**设计，WASP 旨在让本地部署的模型逐步具备：
- **媲美顶尖闭源模型**的复杂 Web 缺陷发现与逻辑推理表现；
- **对标中级授权渗透测试工程师**的系统化作业能力——不仅能识别常见输入处理与配置问题，更能覆盖多租户权限隔离、对象级访问控制、业务工作流状态机等需要跨接口上下文联动的深层安全不变量。

## 三、架构概览与阶段性验证

WASP 采用 **L0 → L5 七层解耦流水线**（侦查建图 → 候选计划 → 混合执行 → 失败升级 → 离线假设 → 规则/人工审校 → 报告生成），层间严格通过运行目录中的结构化 JSON 工件通信，保证每一次测试均可追踪、可复盘、可离线重判。

在最新 `v1.8` 阶段（纯本地 Mac Studio M3 Ultra 环境）的实证数据中，这一架构路线已获得初步验证：

- **确定性 Harness 的杠杆效应**：在主力基准 `harbor-r31` 中，Harness 沉淀了 **73%** 的工程代码，仅消耗 **22%** 的运行时间，却完成了 **57%** 的最终结论裁决；本地模型则专注于主导 **71%** 的广度交互探索。
- **多梯度基准验证**：
  - 在 `hard` 基准集（18 项基准缺陷 / 8 项防误报对照）上，召回率由基线 `16.7%` 提升至峰值 **`66.7%`**（12/18），有效精确率最高达 **`85.7%`**；
  - 在规模大幅扩张的 `harbor` 基准集（**185 个接口**，18 项基准缺陷 / 8 项对照陷阱）上，召回率实现从 `0%` 到 **`33.3%`** 的持续突破，并在 `v1.8` 跑通了**零磁盘增量**的跨租户离线证据链自动判读（V04）。

## 五、演进目标（Roadmap）

WASP 当前仍处于高强度迭代阶段，后续公开报告将持续追踪以下关键突破：

- **能力维度**：将跨租户数据溯源与四态离线判读泛化至对象级越权、业务状态机与数值/幂等不变量，推动百级接口复杂基准召回率向中级安全测试工程师实战水平靠拢；
- **效率维度**：针对长上下文 Prefill 瓶颈（当前占端到端耗时约 98% 的 L2 阶段），引入上下文隔离、轨迹压缩与前缀复用，大幅缩短单轮评估周期；
- **可信度维度**：持续扩大确定性断言覆盖率，压缩无断言主观结论占比，强化面向真实业务“防误报陷阱”的特异性表现。
